# 每日涨停复盘台

抓取 A 股每日涨停池，按**首板、二板、三板、四板及以上**分类，展示每只股票的涨停原因、来源、封板时间、封板资金、开板次数与换手率。

纯静态 HTML + Python 标准库，无需安装第三方 Python 包或启动后端。页面沿用原工作台的蓝色与深色侧栏风格，原固定股票池、评分和持仓模块由涨停复盘功能替换。

## 使用

1. 安装 Python 3.10 或以上版本。
2. Windows 双击 `一键刷新行情.bat`，或在项目目录运行：

   ```powershell
   python sync_limit_up.py
   ```

3. 浏览器打开 `index.html` 或 `股票分析工作台.html`。页面已内嵌本地历史数据，可直接双击打开，无需联网读取数据文件。
4. 点击统计卡片筛选连板梯队；按名称、代码、行业或涨停原因搜索；筛选原因待核实个股；排序并导出当前结果 CSV。

页面的“重新读取快照”仅刷新已生成页面，不执行 Python、不获取新行情。新数据需运行脚本或等待仓库自动任务后刷新网页。

指定日期抓取（仅该日期，不自动回退）：

```powershell
python sync_limit_up.py --date 2026-10-28
```

不指定日期时，以北京时间当天开始，向前最多查询 15 个自然日，选择最近有涨停池的日期。接口错误会报错退出；日期无可用池才回退。休市、尚未开盘、历史范围限制或真实零涨停均可能导致无可用池，本项目不将这些情况直接记为零涨停交易日。页面明确显示实际交易日、请求日期、抓取时间与盘中/盘后状态。

仅根据本地已保存历史重建页面：

```powershell
python sync_limit_up.py --render-only
python -m unittest discover -s tests -v
```

## 批量补抓历史

```powershell
python backfill_limit_up.py --start 2025-10-28 --end 2026-10-27
```

使用腾讯行情的上证指数日线日期作为交易日期参考，抓取同花顺同日历史涨停池及原因；开始日前额外读取 30 个自然日作连板核算预热。仅依赖标准库，单次最多 400 天。

2026-10-28 补抓结果：2025-10-28 至 2026-10-27 共 242 个交易日，16,479 条个股日记录，全部有来源原因标签；其中 36 条连续板数因来源冲突标为待核实。新增 241 份快照，保留原有 2026-10-27 快照，目标区间无失败日期。详见 `data/backfill/report_2025-10-28_2026-10-27.json`。这表示日期齐全，不代表来源完整覆盖全市场；原有 2026-10-28 盘中快照另行保留。

历史数据保存在原有 `data/limit-up/`，已有快照保留不覆盖。来源缓存保存在 `data/backfill/ths/`，再次执行使用缓存续抓；逐日成功、失败、原因覆盖和待核实板数记录在 `data/backfill/report_开始日期_结束日期.json`。失败日期不会伪造空快照，任务结束后重新生成页面。

历史补抓与日常同步的来源范围不同：同花顺历史池按 `HS,GEM2STAR` 口径收录，不保证包含 ST、北交所或全市场所有涨停股票。连续板数按**前一实际交易日是否出现在涨停池**逐日核算，并核对 `首板`、`N天N板` 等明确连续板形态；`4天3板` 不能直接按三连板分类。缺少前序数据或来源形态冲突时，板数标为待核实。来源未返回的封板时间、成交额、行业等字段留空，`open_num=null` 不擅自当作零次开板。页面逐日标明来源。

## 数据与分类口径

- **涨停池**：东方财富 `push2ex.eastmoney.com/getTopicZTPool`。使用 `lbc`（连续涨停天数）分类，`p / 1000` 为价格。接口返回日期、数量和重复代码均进行校验，失败时不发布新快照。历史查询的 `qdate` 可能仍是接口当前交易日，历史数据须另经同花顺明确返回的日期、股票代码和可用价格交叉校验；无法交叉确认时拒绝发布，可能因此无法保存部分历史市场范围的数据。
- **涨停原因**：同花顺 `data.10jqka.com.cn/dataapi/limit_up/limit_up_pool` 的 `reason_type`，验证返回日期并抓取所有分页，按相同交易日及六位股票代码关联。原因展示来源链接；原因抓取失败、数据缺失时明确标注“待核实”，并显示警告与覆盖数量。
- **连续板数与多天多板**：`lbc=1/2/3` 分别为首板/二板/三板，`lbc>=4` 单列高位连板。`4天3板` 不等于三连板，不能使用 `zttj.ct` 或原因源的 `high_days` 代替连续板数。缺失板数进入“板数待核实”。
- **覆盖范围**：依赖东方财富涨停池收录范围，不承诺完整覆盖全部市场或 ST 股票；同花顺原因池与其收录范围可能不同。行业只作背景，不替代原因。
- **时间**：均为北京时间。当天 15:15 前抓取标记盘中快照；其余为盘后抓取快照，但不代表来源已最终更新。两来源分别请求，盘中可能存在短暂差异。
- **历史**：`data/limit-up/YYYY-MM-DD.json` 每日保存一份快照；同日刷新覆盖该日快照，不同日期保留。历史选择器只显示实际保存的日期。公开接口可能只保留近期数据，不能保证补抓任意历史日期。
- **导出**：UTF-8 BOM CSV，含来源和抓取时间，按当前搜索/连板/原因筛选导出。导入 Excel 时将代码列设为文本以保留前导零。

原因是第三方来源的标签归因，未经独立核实，不等于已证明的因果关系。本项目不基于行业、概念或模型编造涨停原因。

## 文件结构

```text
sync_limit_up.py             抓取、校验、归档与页面生成
backfill_limit_up.py         历史区间批量补抓、缓存续抓与交易日连板核算
limit-up.template.html       页面模板与交互逻辑（修改页面请编辑此文件）
data/limit-up/               每日快照
data/backfill/               历史来源缓存与逐日补抓报告
index.html                  生成的首页
股票分析工作台.html           生成的兼容入口
半导体股票分析/               原专题入口，同步生成同一复盘页面
一键刷新行情.bat              Windows 抓取入口
一键同步最新真实行情.py        旧 Python 入口兼容包装
tests/                      分类、来源校验、失败保护与生成测试
.github/workflows/auto_sync_market.yml  每日自动同步
```

GitHub Actions 保留周一至周五北京时间 15:30 的每日任务，支持手动触发。节假日通常回退到最近可用日期；任务会提交快照及生成页面。本仓库工作流只负责生成并提交文件；是否在线可访问取决于仓库已有的 Pages 发布设置。

接口为第三方公开网页数据接口，可能限流、变更或停止服务。主涨停池失败时返回非零退出码，已有快照不会作为新日期数据发布；当日原因接口失败可发布涨停池，但会明确标注原因不可用。历史日期必须通过跨来源校验，原因接口不可用时无法新增历史快照。

数据仅供复盘与研究，不构成投资建议。
